# 设计变更：主视图改为卡片仪表盘

生成于 2026-10-23
Supersedes: `docs/design/2026-10-23-aether-proxy.md` 中「UI 规范（M1）」一节
状态：APPROVED

## 为什么改

原设计把「路由透视（X-Ray）」的密集网格当作主视图（28px 行高、六列、一屏 ≥18 行）。作者随后给出了一张 Aircan 仪表盘的参考图，并明确选择**全面替换**：主视图改为卡片式仪表盘，密集网格降为「连接」页。

这不是配色调整，是视觉世界替换。原 htop 网格的 mockup 与 `DESIGN.md` 一并作废，归档在 `docs/design/mockups/archive/htop-grid/`。

## 改了什么

| 维度 | 原设计 | 现设计 |
|---|---|---|
| 主视图 | X-Ray 密集网格 | 卡片仪表盘（当前节点 / 内核 / 三张速率卡 / 流量折线） |
| 导航 | 无侧栏，单主视图 | 左侧栏：仪表盘 / 节点 / 连接 / 设置 / 日志 |
| 密度 | 28px 行、六列、一屏 18 行 | 卡片式，14px 圆角，留白撑开 |
| 模式切换 | 只在命令面板里 | **顶栏常驻分段控件**：规则 / 全局 / 直连 |
| X-Ray 的地位 | 主视图，产品差异点 | 「连接」页，仍然保留，但不再是首屏 |
| 视觉世界 | htop 进程监视器 | 卡片仪表盘（参考 Aircan 的 Windows 适配） |

## 什么没变

- 代理内核（mihomo）、Electron + React 技术栈、三端渲染一致、v1 只做 Windows 系统代理。
- 数据契约：WS 快照 + 60 秒环形缓冲；`chains[0]` 是实际出站，显示时反转；没有逐连接延迟与成败字段。
- 真实能力清单（M1）：配置导入、节点切换、系统代理、模式切换、连接列表、命令面板、托盘、开机自启。
- 空状态三套（无配置 / 无流量 / 内核失败）的文案与行为。

## 现在失效的验收项

以下几项来自原 UI 规范，随主视图变更失效，需在 M1 验收中替换：

- ~~「1280×800 下不滚动可见 ≥18 行」~~ → 仪表盘首屏验收改为「四块卡片完整可见、折线图不被裁切」。
- ~~「X-Ray 是主视图」~~ → 改为「仪表盘是默认页，连接页从侧栏一步可达」。

键盘六任务、tokens 零裸值、三端布局同构三条仍然有效。
